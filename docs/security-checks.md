# Security checks

The `Security` GitHub Actions workflow runs the `security-checks` job on pull requests and pushes to `main`. Its visible workflow/job label is `Security / security-checks`; GitHub's check-run API exposes the check name `security-checks` under workflow `Security`. The exact context must be confirmed from a completed run before making it required.

The job installs the pinned npm lockfile with lifecycle scripts disabled. It runs ESLint locally with `eslint-plugin-security` and an explicit set of high-confidence JavaScript/TypeScript rules, then audits both npm lockfiles. It fails for high or critical npm advisories, audit errors, or a scanner error. Synthetic benign and unsafe snippets and synthetic audit reports verify that rejection works without executing unsafe code. The rules do not provide comprehensive data-flow analysis or prove the absence of vulnerabilities. Extend them through review and targeted fixtures; do not hide findings with broad suppressions.

`npm audit` sends dependency names and versions to the configured npm registry to retrieve advisory information. Application source, credentials and private keys are not submitted by this workflow. The ESLint run uses local rules and sends no scan results to a third-party service. GitHub Actions still runs on GitHub's infrastructure and uses the account's included private-repository minutes; usage beyond the included allocation depends on the account's settings and plan. No additional paid product is configured by this workflow.

The separate native CodeQL workflow is disabled unless the repository Actions variable `ENABLE_CODEQL` is explicitly set to `true`. Before enabling it, verify that GitHub Code Security is available and authorized for the repository. A skipped CodeQL job is not an analysis result and must not be used as the free required check. Existing branch and code-scanning rules are not modified by this PR. Enabling the workflow does not itself provision GitHub Code Security or override the repository's existing native code-scanning requirement.

For local verification, run `npm ci --ignore-scripts --no-audit`, `node security/test-security.mjs`, `npx --no-install eslint --config eslint.security.config.mjs .`, and `node security/audit.mjs`. The audit requires network access to the configured npm registry and fails closed on invalid responses or errors.
