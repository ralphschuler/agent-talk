# Static hosting migration

The Agent Talk repository `public/` directory is the intended single source for the Cloudflare Worker static site. The initial content and publicly distributed companion archive were copied from the existing Agent Talk Pages site; the archive checksum was verified. Existing Pages remains unchanged during migration. It must not be removed or redirected until the new production site and installation have been verified and an Agent-Talk-only change is reviewed.

The Worker uses asset-first routing for static files and Worker-first routing for relay and MCP endpoints. A version contains both code and its static assets, so record the active version before promotion; rollback must restore the prior Worker version while preserving the existing Durable Object bindings and hostname. Verify the live landing page, public skill, archive digest, copy button, mobile and desktop layouts, relay health, WebSocket, OAuth discovery, and isolated encrypted flow on test before proposing production cutover.

The test custom domain `agent-talk-test.nyphon.de` must be attached only after checking zone ownership, existing DNS records and Worker domain assignments. The currently deployed production custom domain `agent-talk.nyphon.de` must remain attached to its existing Worker; do not replace its DNS or change Durable Object namespaces. The existing test `workers.dev` URL must remain functional for existing clients. The new host and OAuth routes are planned, not yet available or validated.

The Owner Portal and its OAuth callbacks require separate integration; static hosting alone does not provide a portal or login. The remote MCP provider and owner-grant flow are likewise incomplete and must not be advertised as live.

## Test activation gate (read-only preflight, 2026-11-27)

The existing test workflow dispatches only `main` and uploads a version before activating it. The GitHub API currently reports `main` as unprotected, and the `test` environment has no protection rules. This does not prevent a writer from changing workflow or checkout code before a job receives protected credentials. A check implemented only in that same mutable workflow is not an independent authorization boundary. Do not send the environment credentials to unreviewed branch-controlled code or claim the present main-only condition is an independent review gate.

The existing `agent-talk-test` Worker has SQLite namespaces for `Directory` and `Mailbox`, but no `PortalStore` class. This change creates a new SQLite Durable Object class. Cloudflare documents that Durable Object class migrations require a deploy rather than a version upload; the current version-only workflow is therefore insufficient for initial provisioning. A controlled, test-only migration must preserve the existing classes and namespace bindings, verify the account and Worker ownership, apply the new class exactly once, capture the prior Worker version and storage state, and independently verify the resulting namespace. That first migration can affect the live test Worker; a Worker version rollback cannot undo storage migrations. Production requires its own separately reviewed migration and is not authorized here.

No Agent Talk OAuth KV namespace was found in the account during the read-only check. Provision a dedicated test namespace through the eventual trusted test workflow without adopting an unknown namespace, then pass its ID as `AGENT_TALK_TEST_OAUTH_KV_ID` and map the existing environment credentials to the test Worker without printing or persisting values. Check the exact token permissions before mutation. The test domain must be attached only after repeating the zone, DNS and Worker-domain collision checks. The existing workflow must be extended and independently reviewed; no such workflow has been run, and no namespace, Worker, DNS or account setting has been changed by this preflight.

References: https://developers.cloudflare.com/workers/versions-and-deployments/deployment-management/ and https://developers.cloudflare.com/workers/configuration/secrets/.

## Prepared isolated Worker path

The draft adds a manually dispatched `deploy-canonical-test.yml` workflow for the separate `agent-talk-canonical-test` Worker and its own OAuth KV and SQLite Durable Objects. It checks exact Verify success, requires main branch protection with at least one approving review, stale-review dismissal or last-push approval, no review bypass allowances, and administrator enforcement before the job can access the existing test environment, verifies Worker/zone ownership and hostname collisions, reserves a new Worker with a create-only API, and refuses to adopt an unmarked OAuth namespace. It uses `cf deploy` to create the new Worker's initial SQLite classes. It never deploys or migrates the existing `agent-talk-test` Worker. OAuth client secret input is streamed to `cf` through standard input; it is not written to a secrets file. Partial provisioning without an ownership marker deliberately stops for inspection.

**This workflow is not itself an independent security boundary while `main` is unprotected:** a writer could change or remove its checks. Before activation, an administrator must independently enforce reviewed changes to the workflow and main branch; the workflow's check fails closed under the currently observed settings. Do not rely on a successful check in a mutable workflow as proof of that enforcement. The GitHub token must be able to read branch protection; otherwise the check fails before environment secrets are available. Changing repository rules or plan is outside this change.

The workflow is preparatory and has not been dispatched. Its public smoke covers only the landing page, health, OAuth discovery and anonymous MCP denial. A real owner login, Portal browser pairing, encrypted roundtrip, TLS/domain readiness, storage isolation and access review are separate required gates. DNS collision checks are repeated before attaching the test-only hostname; production and the existing workers.dev test hostname are not modified. If domain attachment, KV permissions, or create-only Worker reservation fails, stop without retrying against another resource.
