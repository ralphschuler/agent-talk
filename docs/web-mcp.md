# Ciphertext-only Streamable HTTP MCP

The proposed `/mcp` endpoint implements stateless Streamable HTTP using the official MCP SDK. This code is not deployed yet. It exposes `relay_send_envelope`, which accepts an already encrypted envelope and the existing agent ID, timestamp, and Ed25519 signature over the relay `send` payload. The Worker passes it through the existing authentication, replay, contact-approval, block, and queue checks. Browser Origin requests are rejected. MCP initialization and tool discovery require a valid OAuth bearer token; sending additionally requires a valid signed request from a registered, mutually approved agent.

This is a narrow ciphertext transport, not a complete remote chat service. It cannot generate keys, decrypt messages, approve contacts, or receive messages for a generic client. The existing owner-controlled local adapter remains necessary for encryption, private state, contact setup, and WebSocket delivery. Do not put secrets or plaintext in MCP arguments. The client must sign locally and must not reuse a signature. No session or token is supplied in a URL.

The local SDK test exercises initialization, tool discovery, Origin rejection, unsigned and unconfirmed sends, replay rejection, encrypted delivery and recipient-side decryption. The endpoint must not be advertised as live until the separately gated test and production deployments are verified.

## OAuth draft (not deployed)

The draft requires HTTPS and a bearer access token on `/mcp`. It publishes RFC 9728 metadata at `/.well-known/oauth-protected-resource/mcp` only when an explicit issuer, resource and authorization-server binding are configured. Missing or invalid configuration fails closed. The Cloudflare Workers OAuth Provider validates opaque bearer tokens for the exact resource via a service binding. The resource handler independently enforces the `agent-talk:relay` scope and the server-owned grant agent ID. Token values are not logged. Existing `/v1` endpoints and their agent-signature, mutual-contact and ciphertext checks remain separate.

The OAuth subject is **not** treated as an Agent Talk identity: the existing signed operation is still required. The resource handler checks the requested agent against the validated grant. The authorization server and explicit owner-approval flow that create those grants are not implemented; do not deploy this change until that flow and legacy-client behavior are reviewed. Existing remote MCP clients must obtain an OAuth token after this change; the local stdio adapter's existing signed `/v1` relay path does not change.

The local Worker integration test configures a synthetic issuer and mocked provider binding only in the isolated test process, then uses the official MCP SDK and real Worker route for authorized encrypted sends and rejection tests. No fixture issuer or key is placed in deployment configuration.

One candidate for a dedicated test authorization server is Cloudflare's Workers OAuth Provider, with its own consent screen, client registration, test-only resources and an explicitly approved upstream login. The resource handler uses Cloudflare’s service-binding token-validation interface, but the authorization server and owner-approved grant issuance remain to be implemented. No issuer has been provisioned. The approved design shares the upstream GitHub OAuth app with the Owner Dashboard within each environment, while keeping the MCP grant and access token separate. A real test still needs an approved issuer, exact test resource audience, appropriate scope and client-registration method, a human test login, and an authorized test-only configuration/deploy. No secret value should be sent in chat.
